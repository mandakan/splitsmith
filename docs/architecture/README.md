# Architecture diagrams

Interactive, self-contained HTML diagrams (pan/zoom, search, guided views,
light/dark, PNG/SVG export from the viewer's Export menu). Open them in a
browser; GitHub does not render them inline.

| Diagram | Type | What it shows |
| --- | --- | --- |
| [`splitsmith.html`](splitsmith.html) | architecture | System view: SPA -> FastAPI -> Postgres jobs -> worker -> engine, plus CLI/MCP, share links, storage, ffmpeg |
| [`stage-status.html`](stage-status.html) | lifecycle | `StageStatus` (`todo` -> `partial` -> `ready` -> `in_progress` -> `audited`, `skipped`) and what does and does not move it |
| [`stage-detection.html`](stage-detection.html) | workflow | Per-stage job chain: beep detect, confidence gate, HITL queue, trim, shot ensemble, audit document |
| [`share-link.html`](share-link.html) | sequence | Anonymous share preview: shell -> in-process sub-request -> `_share_alias` -> og-meta; content-addressed card image; uniform failure |
| [`data-model.md`](data-model.md) | ER (Mermaid) | The twelve hosted tables, generated from `db/models.py`, with the logical `(user_id, match_id)` joins the foreign keys do not express |

Each `*.json` next to an HTML file is its [Archify](https://github.com/tt-a1i/archify)
source. The architecture spec carries `sources` paths per node, verified
against the pinned `meta.repository.revision` at render time; the viewer's
`SRC` badges link to them on GitHub. The ER diagram is regenerated by
`scripts/gen_er_diagram.py` (`--check` verifies it is current).

To regenerate an Archify diagram after changing its spec:

```bash
node <archify>/bin/archify.mjs deliver <type> docs/architecture/<name>.<type>.json \
  docs/architecture/<name>.html --quality showcase [--repo-root .]
```

`--repo-root` applies to the architecture diagram only; bump
`meta.repository.revision` to the commit whose file paths you are citing.
Per-module detail lives in SPEC.md under "Module responsibilities".
