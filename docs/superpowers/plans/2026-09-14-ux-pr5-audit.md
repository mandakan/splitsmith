# UX PR 5: Audit with beep confirmation as step 1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the Audit page on the primitives (PageHeader, one transport line, one current-shot line, flags-first shot list, shortcuts footer) and fold beep confirmation into it as step 1, so the Beep review page can go.

**Architecture:** `pages/Audit.tsx` keeps every hook, effect, keyboard handler and save path it has; only its render tree changes, and its beep entry points (`openBeepReview`, the banner's deep-link) become an in-page step. Step 1 is a new `components/audit/BeepStep.tsx` built on the existing `useBeepQueue` workflow hook and the existing `BeepWaveformPicker`, so the confirm chain (mark reviewed, trim if uncached, shot_detect -- `set_beep_reviewed` semantics, fixed to chain in #970) is unchanged server-side. The flags-first ordering and the "does this stage need step 1" rule live in a pure `lib/auditStep.ts` with tests.

**Tech Stack:** React 19, Tailwind 4, vitest; `corepack pnpm typecheck | lint | test | build` in `src/splitsmith/ui_static`. Seeder in `scripts/seed_demo_match.py` (Python, ffmpeg on PATH for `--media`).

**Spec:** `docs/superpowers/specs/2026-09-13-ux-restructure-and-visual-budget-design.md` s4.4, s5, s6. Mockup: https://claude.ai/code/artifact/771ff60e-bb26-418e-9f3c-bc76f86de5dd

## Decisions taken on the mockup (2026-09-14)

1. Shot list in the right column under the video, flags first, rejected candidates struck through and dim; the L drawer goes from Audit.
2. Re-pick from step 2 returns to step 1 in place with the current beep selected; nothing is invalidated until Confirm on a different time. Cancel returns to step 2 untouched.
3. Marker filters are one "show" summary on the transport line that opens a menu of toggles; the five pills go.

## Global Constraints

- Visual budget (spec s5, CLAUDE.md): primitives only; no `text-[...]`, `tracking-[...]`, `font-display` outside `components/ui`; one `Button variant="primary"` per view (Save & next in step 2, Confirm & next in step 1); red = brand, primary, current shot, focus; amber = flags and running state; glow only on live state; no flavour copy.
- Files rebuilt here drop their grandfather line: `pages/Audit.tsx`, `pages/MobileAudit.tsx`, `components/audit/PrereqGate.tsx`, `components/audit/SessionSummary.tsx`, `components/audit/mobile/WrappedWaveform.tsx`, `components/audit/AnomalyPins.tsx` (if it has one). Files deleted: `pages/BeepReview.tsx`, `components/audit/StageChipRail.tsx`, `components/audit/ShortcutHints.tsx`, `components/audit/BeepAnomalyBanner.tsx`, `components/audit/StageActionBar.tsx`, `components/audit/BeepStatusChip.tsx`. Files that stay grandfathered and untouched: `components/BeepSection.tsx` (the picker), `components/Waveform.tsx`, `components/MarkerLayer.tsx`, `components/VideoPanel.tsx`, `components/audit/MultiCamColumn.tsx`, `CamGridModal.tsx`, `CamSyncPill.tsx`, `components/HelpOverlay.tsx`, `components/ListDrawer.tsx` / `ShotStepper.tsx` / `AuditControls.tsx` (still used by `pages/Review.tsx`), `components/audit/AnomalyChips.tsx` (still used by Triage until PR 8), `pages/MobileBeepReview.tsx` (the phone's beep surface stays).

import type { StageEntry, StageVideo } from "@/lib/api";

export interface ShotRow { marker: AuditMarker; index: number | null; flag: string | null; rejected: boolean }
